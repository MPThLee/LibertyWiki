# 13. AGPL-3.0 및 클린룸 구현·소프트웨어 공급망 정책

## 1. 제품 라이선스

프로젝트 자체의 신규 소스 라이선스는 **GNU AGPL-3.0-only**를 기본으로 합니다. 배포물에는 정식 LICENSE 본문, SPDX 식별자, 저작권·기여자 고지, 서드파티 NOTICE 및 Corresponding Source 제공 경로를 포함합니다. 네트워크를 통해 이용자가 수정된 AGPL 소프트웨어와 상호작용하는 상황에 대한 제13조 의무를 배포 방식별로 검토합니다.

AGPL로 배포하더라도 별도 서비스 이용료/지원료/호스팅 요금을 받을 수 있는지 등의 문제와 소프트웨어 저작권 의무는 구분해야 하며 계약·재배포 조건은 법률검토가 필요합니다. 본 문서는 법률 자문이 아닙니다.

## 2. 원본 재사용 금지(프로젝트 정책)

**금지:** MediaWiki 코어, Parsoid, 각 번들/서드파티 확장·스킨의 프로그램 코드(CSS, JS, PHP, SQL, XML 구현 코드 포함), 테스트 소스, 내부 자료구조 코드, 로직 번역/자동 변환/AI 포팅, 복제·내장·링킹·미세 수정 재사용.

**허용 범주:** 원본의 공개된 사용자 기능, 외부 API 입력/출력·에러·프로토콜 등 **인터페이스 명세와 관찰 가능한 동작**, 위키텍스트라는 데이터 형식의 규칙, 공개 운영 문서 및 설계 개념을 분석하고 *독자적인 설계*를 작성합니다. 실제 위키 문서·미디어·덤프를 사용한다면 **개별 콘텐츠 라이선스·서비스 약관·개인정보 보호**는 별개로 검토합니다.

본 프로젝트가 저작권법상 클린룸 방어를 자동으로 확보한다는 의미는 아닙니다. 외부 공개 API의 문서화와 재현 행위 역시 관련 법규·약관을 준수하며 법률 검토 게이트를 거칩니다.

## 3. 개발 프로세스

- 역할 분리: **명세·관찰 팀**은 외부 동작, 공개 문서, 테스트 입력·출력을 기록하고, **구현 팀**은 정리된 기능 계약만으로 독립 코드 작성.
- 출처 기록: 요구 ID, 공식 문서 URL/확인일, 테스트 fixture 생성 방식 및 담당자를 추적합니다. 소스코드로부터 생성된 직역/구현 의사코드 투입 금지.
- AI 코딩 에이전트: URL·원본 소스를 붙여 넣어 '이 코드 Kotlin으로 변환'을 요구할 수 없습니다. 기능 설명/입출력/수용 기준만 전달합니다.
- PR에는 구현 자가 확인 및 provenance 체크리스트를 남깁니다. 문자열·파일·블록 단위 유사도 스캔은 보조수단이며, 무결한 법적 보증은 아닙니다.
- 오픈소스 의존성 사용은 원본 MediaWiki 코드 재사용 금지와 별도입니다. Kotlin/Java, Parser 라이브러리, DB 드라이버, 이미지 처리 라이브러리 등은 라이선스 적합성과 코드 원산지를 확인한 뒤 승인합니다.
- Third-party license: AGPL/GPL/LGPL/MPL/Apache/MIT/BSD 등 결합 시 `linking`, source-offer, copyright notice, patent, 제공방식 위험을 법률검토합니다.

## 4. 빌드와 배포

SBOM(CycloneDX/SPDX), 이미지 digest와 서명, lockfile, SLSA/빌드 로그, 취약점 확인, release source archive, reproducible build 지향, 공개 웹 UI source-offer 안내가 배포 게이트입니다. 라이선스 텍스트 자체는 **원본 공식 라이선스를 완전한 형태로 사용**하며 이 문서에서는 라이선스 본문을 재서술하는 것으로 대체하지 않습니다.
